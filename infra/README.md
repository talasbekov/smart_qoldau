# Инфраструктура

Два контура. Разработка — `docker-compose.dev.yml` (пароли в файле, порты
наружу, данные в контейнерном слое: удобно и одноразово). Пилот и бой —
`docker-compose.prod.yml` плюс `.env` рядом.

## Контур пилота

```bash
cp .env.prod.example .env      # заполнить своими значениями
docker compose -f docker-compose.prod.yml --env-file .env build
docker compose -f docker-compose.prod.yml --env-file .env up -d
docker compose -f docker-compose.prod.yml --env-file .env ps
```

Дальше — засеять справочник тем и завести первого суперадмина:

```bash
docker compose -f docker-compose.prod.yml --env-file .env run --rm \
  -e DATABASE_URL=postgresql://... backend node dist/prisma/seed.js
```

(сид написан на TypeScript и в рантайм-образ не попадает; на площадке без
исходников проще выполнить `prisma/seed.ts` из сборочного образа или
завести темы SQL-скриптом — способ зависит от того, как у вас устроен
выкат).

Суперадмин заводится сам при старте, если задать `ADMIN_BOOTSTRAP_EMAIL`
и `ADMIN_BOOTSTRAP_PASSWORD`; после первого входа обе переменные из
окружения убрать.

## Почему так, а не иначе

**Миграции накатывает отдельный одноразовый сервис `migrate`, а не API при
старте.** С двумя репликами оба процесса стартуют одновременно и лезут
менять схему параллельно — Prisma честно ловит это блокировкой, но
получается гонка на ровном месте. Здесь API ждёт успешного завершения
миграции (`service_completed_successfully`) и только потом поднимается.

**База, Redis и хранилище — во внутренней сети без публикации портов.**
Наружу смотрит только реверс-прокси (в компоузе его нет: сертификаты и
домены зависят от площадки). Открытый наружу Postgres — самая частая
причина «нас взломали» в проектах такого размера.

**Redis с `appendonly yes`.** В нём живут лимиты троттлинга, дедлайны
неотвеченных офферов и presence экспертов. Перезапуск без persistence
обнуляет счётчики лимитов и теряет дедлайны — заявки зависают в
`SEARCHING` до ближайшего sweep.

**Адрес API вшивается в бандл админки на этапе сборки.** Vite подставляет
`import.meta.env` в код, поэтому для staging и прода нужны РАЗНЫЕ образы
админки. Один образ с разными переменными окружения тут не работает — это
не наша прихоть, а как устроен Vite.

**Рантайм-образ бэкенда без dev-зависимостей.** `npm ci --omit=dev`: среди
dev-зависимостей живёт `prisma` CLI — единственный источник оставшихся
уязвимостей аудита (3 штуки на 2026-08-26), и в бою ему делать нечего.
Миграции при этом в образе есть — их применяет сервис `migrate`, который
поднимает `npx prisma migrate deploy` из того же образа.

**Контейнеры работают не от root** (`USER node`): пробитый через загрузку
файлов процесс не должен получать права на весь образ.

## Размер образа бэкенда

~840 МБ, из них ~450 МБ — прод-зависимости и ~100 МБ движок Prisma. Это
много, но честно: Prisma тащит нативный движок запросов, а AWS SDK —
свой транспорт. Что сделано, чтобы не было хуже: multi-stage (исходники и
dev-зависимости в рантайм не попадают), `npm ci --omit=dev`, и клиент
Prisma не дублируется — из сборочного слоя копируется только
`node_modules/.prisma`, потому что `npm` его не создаёт (postinstall
пропускается без prisma CLI), а сам пакет `@prisma/client` ставится как
обычная прод-зависимость. Дубль стоил 104 МБ.

Дальше сжимать можно `binaryTargets` в схеме Prisma под конкретный
рантайм — но выигрыш десятки мегабайт, а цена — образ, который перестаёт
запускаться на другой платформе. Пока не нужно.

## Чего здесь намеренно нет

- **TLS и реверс-прокси.** Зависит от площадки: Caddy, nginx, ALB. Нужен
  контейнер в сети `edge`, который терминирует TLS и проксирует на
  `backend:3000`, `admin:80`, `landing:3000`.
- **Бэкапы.** Тома `pgdata` и `miniodata` надо снимать по расписанию;
  документы верификации и содержимое чата не восстанавливаются ниоткуда.
- **Реплики и балансировка.** Приложение к ним готово (лимиты и presence
  в Redis, миграции отдельным шагом), но масштабирование — решение
  площадки.
- **LiveKit.** В dev поднимается локально `--dev`; в бою это отдельный
  сервис со своими сертификатами и TURN, разворачивается вне этого файла.
