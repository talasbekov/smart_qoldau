# Ручная проверка связи на стенде

Адрес: `https://tormentedly-roomy-toney.ngrok-free.dev`. Используйте русскую версию `/ru` — названия кнопок ниже соответствуют ей. Это инструкция для нового ручного прогона, а не утверждение о результате проверки VPS.

## Подготовленные тестовые аккаунты

- Клиент: `+77000001981`.
- Специалист: `+77000001982` (TESTONLY Manual Expert).
- Тема: **TESTONLY Проверка связи**. Карта клиента: **1111**, тестовый провайдер; реального списания нет.
- Расписание тестового специалиста подготовлено на все дни. Включите «Принимаю клиентов» и держите кабинет открытым.
- Если ngrok показывает промежуточную страницу, нажмите **Visit Site**.

После запроса кода оператор получает свежие SMSdev-коды на VPS:

```bash
ssh root@84.247.162.192 'docker logs --since 5m smartqoldau-backend-1 2>&1 | grep "SMS -> +7700000198"'
```

Коды разные для двух номеров, действуют пять минут; SMS на телефон не отправляется. На номер действует ограничение: три запроса кода в час.

## Подготовка

- Два участника: клиент и **заранее подготовленный специалист**. Откройте сайт на двух устройствах либо в двух независимых профилях браузера. Две обычные вкладки одного профиля используют общую сессию и не подходят для входа под разными аккаунтами.
- Для аудио/видео нужны HTTPS, разрешения микрофона/камеры и наушники. Держите окно специалиста видимым: в неактивной вкладке приём заявок может приостанавливаться.
- Оператор должен подтвердить, что специалист имеет статус `VERIFIED`, не заблокирован, поддерживает нужную тему и все три формата. В его разделе **«Расписание»** текущее время Алматы должно попадать в рабочий интервал вне перерыва.
- У тестового клиента должен быть **сохранённый тестовый способ оплаты**. В web нет формы добавления карты: checkout лишь выбирает уже сохранённую. Подготовить его можно через мобильное приложение либо оператором через штатный API. Не подменять платёж простым изменением статуса в БД: для последующего завершения нужен настоящий hold в тестовом провайдере.

## Вход

1. Клиент открывает `https://tormentedly-roomy-toney.ngrok-free.dev/ru/login`, вводит свой тестовый номер в формате `+77XXXXXXXXX`, нажимает **«Получить код»**, затем вводит шесть цифр в **«Код из SMS»** и нажимает **«Войти»**.
2. Специалист выполняет те же действия в другом профиле/устройстве под своим номером. После входа может открыться общий профиль — перейдите в кабинет специалиста вручную: `https://tormentedly-roomy-toney.ngrok-free.dev/ru/expert`.
3. Если на стенде включён `SmsDevProvider`, SMS на телефон **не приходит**. Оператор берёт свежий код для соответствующего тестового номера из backend-лога вида `SMS -> <номер>: SmartQoldau: код входа <код>`. Код действует пять минут; фиксированного общего кода нет. Не сохраняйте OTP, токены и номера в отчёт или скриншоты. При `SMS_PROVIDER=mobizon` используется реальная доставка SMS.

## Обычный путь к оплаченной активной консультации

Повторите этот блок **отдельно для «Чат», «Аудио» и «Видео»**, завершая предыдущую консультацию перед следующей. Переключателя формата внутри текущей встречи в web нет.

1. Специалист в кабинете включает **«Принимаю клиентов»**, открывает **«Заявки»** (`/ru/expert/offers`) и оставляет окно видимым.
2. Клиент открывает `https://tormentedly-roomy-toney.ngrok-free.dev/ru/requests/new`. При первом обращении на экране **«Прежде чем начать»** читает условия, заполняет **«Как к вам обращаться»** и нажимает **«Продолжить»**.
3. Клиент выбирает согласованную тему в **«С чем нужна помощь»**, нужный вариант **«Формат консультации»**, оставляет **«Нужна помощь срочно»** выключенным и нажимает **«Найти специалиста»**.
4. Специалист принимает появившуюся заявку кнопкой **«Принять»**, пока предложение действительно. Обе стороны переходят к консультации; её статус — **«Идёт сейчас»** (`ACTIVE`). Если заявка не пришла, сначала проверьте подготовку специалиста, расписание и видимость его окна.
5. Клиент нажимает **«Оплатить консультацию»**, выбирает сохранённый тестовый способ и нажимает **«Оплатить»**. Дождитесь возврата в консультацию и появления чата/кнопки подключения. Это путь к `ACTIVE + HELD`; до подтверждённого холда доступ к общению закрыт.
6. Если специалист открыл консультацию до оплаты и ещё видит ограничение доступа, обновите его страницу после успешной оплаты клиента.

**Ограничение оплаты:** сейчас backend использует `MockPaymentProvider`; checkout прямо сообщает о тестовом платёжном контуре. `HELD`, `CAPTURED` и `VOIDED` здесь подтверждают работу приложения и mock-провайдера, а не банковскую операцию. Не используйте реальные реквизиты. При **«Нет сохранённых способов оплаты»** подготовьте тестовый способ и нажмите **«Обновить способы оплаты»**. При неопределённом результате нажимайте **«Проверить статус»**, а не создавайте повторную оплату.

## Три проверки связи

| Формат | Действия | Ожидаемый результат |
|---|---|---|
| Чат | Клиент вводит уникальную фразу в **«Сообщение»**, нажимает **«Отправить»**. Специалист отвечает другой фразой. Обновите одну страницу. | Обе фразы видны у обоих участников, отправленный текст очищается после подтверждения; после обновления история сохраняется без дублей. |
| Аудио | Оба выбирают **«Микрофон»** и нажимают **«Подключиться»**. По очереди произнесите разные фразы. Выключите и включите микрофон кнопкой **«Микрофон включён» / «Микрофон выключен»**. | Каждый слышит другого; выключенный микрофон не передаёт речь, после включения речь снова слышна. Камера не требуется. Чат рядом также работает в обе стороны. |
| Видео | Оба выбирают **«Камера»** и **«Микрофон»**, нажимают **«Подключиться»**. Каждый машет рукой и произносит фразу. По очереди выключите/включите камеру и микрофон. | Каждый видит движущееся изображение именно собеседника и слышит его. После повторного включения камеры возвращается **живое движение**, а не только последний кадр; звук также восстанавливается. |

В каждой аудио/видеоконсультации один участник нажимает **«Выйти из звонка»**, затем снова **«Подключиться»**. Второй остаётся на странице. Проверьте восстановление двусторонней связи и сохранность чата. Выход из звонка **не завершает консультацию**.

## Завершение и чтение истории

1. Специалист при желании заполняет **«Приватная заметка»**, нажимает **«Сохранить заметку»** и проверяет сообщение **«Заметка сохранена»**. Клиент эту заметку не видит.
2. Специалист выбирает **«Консультация состоялась»** в **«Исход консультации»**, нажимает **«Завершить консультацию»**, затем **«Подтвердить завершение»**.
3. Дождитесь **«Консультация завершена»** и отдельного подтверждения расчёта `CAPTURED`. Само завершение без подтверждения расчёта ещё не доказывает успешное списание даже в mock-контуре.
4. **Не обновляя страницу клиента вручную**, проверьте автоматический переход к завершённой консультации: кнопка **«Отправить»** исчезла, история осталась читаемой; в аудио/видео звонок отключился у обоих, индикаторы использования камеры/микрофона погасли. Обычно срабатывает событие; резервная проверка идёт каждые 15 секунд плюс время ответа сервера.
5. Обновите обе страницы: статус остаётся завершённым, чат не позволяет новую отправку, подключение к звонку не предлагается. Для следующего формата создайте новую заявку.

Запишите по каждому формату: время, идентификатор консультации из URL, результат чата/звука/видео, выключения/включения, повторного подключения и завершения. При сбое приложите текст ошибки и скриншот без личных данных; не прикладывайте cookies, OTP или медиатокены.
