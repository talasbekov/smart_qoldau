# VPS update — 19 сентября 2026

Площадка: `84.247.162.192`, `/opt/smart-qoldau`.
Публичный web: https://tormentedly-roomy-toney.ngrok-free.dev/ru

Обновлены backend, web и admin из текущей рабочей копии. Сохранены существующие секреты и тома PostgreSQL/Redis/MinIO. Перед обновлением сохранены архив исходников с конфигурацией, `pg_dump -Fc` и rollback-теги трёх образов; каталог `/opt/smart-qoldau-backups/20260919-web-update` доступен только root.

Добавлены LiveKit v1.13.5 и ngrok на VPS. Старый локальный контейнер `goals-ngrok-1` остановлен, его автоматический перезапуск отключён, чтобы один токен не конфликтовал между проектами. Остальные локальные проекты не останавливались. На VPS ngrok и LiveKit имеют `restart: unless-stopped`.

HTTPS/WSS сигнализация идёт через ngrok и nginx `/livekit/`; WebRTC передаёт медиа напрямую на VPS (UDP7882, запасной ICE TCP7881). Порт сигнализации7880 и диагностический ngrok4040 не опубликованы наружу. TURN/TLS не настроен: работа через сети, блокирующие эти медиапорты, не подтверждена. Настройки портов сверены с [документацией LiveKit](https://docs.livekit.io/transport/self-hosting/ports-firewall/).

Конфигурация запуска:

```bash
cd /opt/smart-qoldau/infra
docker compose -f docker-compose.prod.yml -f docker-compose.initial.yml -f docker-compose.ngrok-media.yml --env-file .env up -d --no-build
```

`infra/.env`, `infra/ngrok.yml`, `infra/livekit.vps.yml` содержат секреты, их нельзя коммитить или прикладывать к отчётам. Для ngrok конфигурация600 принадлежит UID1000/GID100 его контейнера. Остальные секреты root600. В nginx добавлено проксирование LiveKit и сохранение HTTPS-протокола исходного запроса за туннелем.

Тестовые пользователи созданы insert-only операторским скриптом `backend/scripts/prepare-manual-communications.cjs` с явным подтверждением БД `smartqoldau` и провайдеров dev/mock. Реальные пользователи не изменялись. Код авторизации получен штатным OTP API; согласие тестового клиента и расписание специалиста настроены через API. Каждая проверочная консультация создаётся через request → offer.accept → pay; статусы ACTIVE/HELD не проставляются вручную.

SMS_PROVIDER=dev: SMS только в журнале. PAYMENT_PROVIDER=mock: банковских списаний нет. Это тестовая площадка, не запуск реальных консультаций.

Ручные шаги и тестовые номера: [manual-test.md](manual-test.md).
