# web

Веб-приложение SmartQoldau — Next.js (App Router, TypeScript),
Tailwind CSS, локализация `next-intl` (`/ru/*`, `/kz/*`),
Jest + React Testing Library.

Каталог вырос из лендинга (эпик E10) и с эпиком E16 стал приложением
целиком: маркетинговые страницы, публичный каталог и профили
специалистов, кабинеты клиента и эксперта. Маршруты разведены на три
группы внутри `app/[locale]/`:

- `(public)` — всё, что видит аноним, с серверным рендером и индексацией;
- `(client)` — кабинет клиента (план B эпика E16);
- `(expert)` — кабинет эксперта (план C эпика E16).

Скобки в именах групп на адреса не влияют: `(public)/about/page.tsx`
по-прежнему отдаётся по `/ru/about`.

Независим от Flutter-пакетов (`app_client`, `app_expert`,
`packages/shared`) — обычное Node/Next.js-приложение со своим
`package-lock.json` (тот же паттерн, что `backend/`; в этом монорепо npm
workspaces не используются).

## Запуск

```bash
npm install
npm run dev            # http://localhost:3000 — конфликтует с backend/, см. ниже
npm run dev -- -p 3100 # если backend уже поднят на :3000
```

Витрина специалистов на главной (`GET /experts`) и форма поддержки
(`POST /tickets`) обращаются к живому бэкенду — по умолчанию
`http://localhost:3000/v1` (переопределяется `NEXT_PUBLIC_API_BASE_URL`).
Без поднятого бэкенда витрина специалистов просто показывает пустое
состояние, форма поддержки — ошибку сети при отправке.

## Структура

```
app/
  layout.tsx              — пробрасывает children; редирект "/" -> "/ru"
                             делает middleware.ts (next-intl), НЕ этот layout
  sitemap.ts, robots.ts
  [locale]/                — все страницы под локалью ru|kz, html/body здесь
middleware.ts               — next-intl, локаль по пути
components/                — Header, Footer, SpecialistCard, FaqAccordion,
                              SupportForm, LegalPageLayout
lib/
  api.ts                   — fetchPublicExperts, submitTicket
  ticket.ts                — buildTicketPayload (чистая функция)
  i18n/                    — routing.ts, request.ts, navigation.ts (next-intl;
                              Link/redirect/useRouter — из createNavigation,
                              next-intl v4 не экспортирует их из корня пакета)
messages/                  — ru.json, kz.json
```

Документация разработки находится в отдельном Obsidian-хранилище
`smart_qoldau_vault`: `WIKI/plans/` (E16A/B/C),
`WIKI/planning/2026-09-15-MVP-CONTINUATION.md` (результаты последующих работ)
и `docs/Прототип/` (экспорт экранов). На текущей рабочей машине хранилище
лежит в `../Obsidian_brain/smart_qoldau_vault` относительно корня репозитория.
Старые ссылки на `brain/` внутри репозитория больше не актуальны.

## Известные ограничения

- Каталог, материалы, подбор, кабинеты клиента и эксперта реализованы
  отдельными маршрутами. Поддержка включает список обращений и переписку.
- Цена Premium загружается из `GET /premium/plans`. Решение владельца
  от 2026-09-02: 4 990 ₸/мес; текущий производный годовой тариф — 39 900 ₸.
  Прототип не заменяет актуальный API-контракт и продуктовые решения.
- На проверенном 2026-09-19 локальном стенде `localhost:8080` работает
  старый backend image от 2026-09-02: публичный `/v1/content` возвращает 401,
  хотя исходный код уже использует optional-auth. Прохождение unit-тестов
  не означает, что этот стенд обновлён. Подробности проверки —
  `../docs/qa/web-2026-09-19/`.

## Браузерные проверки

```bash
npx playwright install chromium  # один раз для установленной версии Playwright
npm run e2e                     # build + standalone server на :3100
```

Тестам нужен API по `NEXT_PUBLIC_API_BASE_URL` (по умолчанию
`http://localhost:8080/v1`). Проверки с synthetic fixture подменяют вход;
они проверяют интерфейс и переходы, но не реальную доставку SMS,
проведение платежа или двусторонний звонок.

## Ручная проверка против живого бэкенда (пройдена)

Все 6 страниц на обеих локалях отдают 200, витрина специалистов на
главной рендерит реального верифицированного эксперта из БД
(`GET /experts`), форма поддержки успешно создаёт тикет
(`POST /tickets` → `201`, проверено прямым запросом с телом, которое
собирает `buildTicketPayload`). Найден и исправлен реальный баг при
проверке: корневой `app/layout.tsx` безусловно вызывал
`redirect('/ru')`, что применялось абсолютно ко всем маршрутам (включая
уже `/ru`) — Next.js рендерит корневой layout как предка каждого
дочернего маршрута — и приводило к самозацикленному редиректу `/ru` →
`/ru`. Исправлено: редирект "/" -> "/ru" отдан целиком middleware.ts
(next-intl, `localePrefix: "always"` по умолчанию уже это делает),
`app/layout.tsx` теперь просто пробрасывает `children`.

## Кабинет и почему браузер не ходит в API напрямую

Публичные страницы рендерятся на сервере и ходят в NestJS оттуда же.
Всё, что за логином, идёт через **BFF**: токены лежат в httpOnly-cookie,
браузер их не видит, а запросы кабинета проксирует `/api/proxy/*`,
подставляя `Bearer` уже на сервере.

Смысл ровно один: XSS — свой скрипт или заехавший с чужой
зависимостью — не должен уносить доступ к переписке с психологом.
С токеном в `localStorage` он уносил бы её вместе с возможностью
продлевать сессию бесконечно.

У прокси есть **белый список** первых сегментов пути. Без него он стал
бы открытым ретранслятором ко всему API от имени вошедшего человека,
включая `/admin/*`.

Два исключения, где браузер всё же обращается наружу сам:

- **socket.io** (чат, события заявок и консультаций),
- **LiveKit** (видео и звук).

Проксировать через Next поток бессмысленно, поэтому им выдаётся
**короткоживущий access-токен** отдельным маршрутом `/api/realtime/token`.
Refresh-токен там не появляется никогда: украденный access даёт окно в
минуты, refresh дал бы бессрочный доступ.

При истечении access-токена защищённый маршрут проходит через
`/{locale}/renew-session` и возвращается к исходной странице. Ротация
выполняется `POST /api/auth/refresh`; ответ содержит только сведения о
пользователе и срок действия. Сами токены остаются в httpOnly-cookie.
Вход, выход и обновление сериализуются через Web Locks; смена аккаунта
инвалидирует старый документ и realtime-подключение. Для этих операций
нужны Web Locks и localStorage: используйте HTTPS либо localhost.
Неопределённый результат обновления не приводит к повтору прикладного
POST — при необходимости пользователь входит заново.

## Лок-файл считается в образе сборки

`npm ci` в контейнере падал с «Missing: @emnapi/... from lock file», хотя
локально всё ставилось. Причина — разные версии npm: на машине 11.6.2, в
`node:24-slim` 11.17.0, и они по-разному разрешают платформенные
опциональные пакеты (`@img/sharp-wasm32`, `@unrs/resolver-binding-*`).

Поэтому после изменения зависимостей лок пересчитывается в той же среде,
что собирает образ:

```bash
docker run --rm -v "$PWD":/app -w /app node:24-slim npm install --package-lock-only
```

Обычный `npm install` на машине лок тоже обновит, но собранный им образ
может не собраться.
